# FTPView

本地运行的 React + Node.js FTP 客户端。

```sh
npm install
npm start
```

访问 http://localhost:5173 。后端仅监听 127.0.0.1:3001。

## 重启与停止

```sh
npm run restart
```

新版启动器记录自己的服务，重复 `npm start` 会提示已有实例，不会再开一个端口。`npm run restart` 停止本项目启动器管理的实例后启动新实例；不会结束其他项目的进程。首次从旧版升级时，请先在旧终端按 Ctrl+C 停止旧实例，再使用新版命令。

前端热更新；server.js、ftp-connection.js、transfers.js 修改后自动重载后端。传输期间自动重载会延后，重启/停止请求会被拒绝，避免主动中断传输。强制结束进程、系统关机或断网仍可能中断传输。

## 文件传输

1. 打开页面自动加载上次本机目录，默认隐藏点文件。
2. 填写 FTP/FTPS 配置并连接。配置（包括密码）保存在当前浏览器，可点击“忘记连接信息”清除。
3. 单击左侧普通文件，点击“上传文件”；或选择右侧普通文件，点击“下载文件”。
4. 在传输列表查看状态；完成后刷新目标面板。

目前一次传输一个普通文件，不支持整个文件夹、符号链接、暂停或断点续传。

### 完整性保护

- 传输是复制，始终保留源文件。
- 下载先写 `.ftpview-part-*`，完成大小与 SHA-256 校验后通过不覆盖目标的原子硬链接发布。存在同名文件时拒绝操作。目标文件系统不支持硬链接时明确失败，不退回不安全的覆盖操作。
- 上传先用 MKD 创建独立 `FTPView-UUID` 目录，保留原文件名。普通 FTP 没有标准化的“不覆盖改名”，独立目录用于隔离目标，避免覆盖当前目录内的同名文件。
- 上传临时文件后回读远端内容，比较 SHA-256，检测本机源文件是否在传输期间变化，再改为正式文件名。
- 下载会再次读取源文件并比较 SHA-256，检测读取结果是否一致。回读校验会增加网络流量和耗时；服务器不允许读取或 SIZE 查询时会报错，不跳过校验。
- 失败时临时文件可能保留，界面显示位置，未校验的文件不标记完成。重启后内存任务列表清空，临时文件保留以供检查，不自动删除。
- 校验保证所读取内容一致，无法保证服务器后续不修改数据或硬盘故障不丢数据。请在传输期间保持源文件不变；独立目录也不应被其他客户端同时修改。

## 检查

```sh
npm test
npm run build
```

测试包含目录读取、编码和 FTPS 参数、模拟传输中断、同名冲突、内容损坏和目标并发创建。仍需在实际 FTP 服务器上验证权限与兼容性。
